# Security policy

## Reporting a vulnerability

Please do not publish credentials, exploit instructions, or sensitive data in public Issues or PRs.

For a public Panghuli Studio repository, open its **Security** tab, choose **Report a vulnerability**, and submit a private report. Include the affected version, reproduction steps, impact, and a proposed fix if you have one.

If the private reporting option is unavailable, open an Issue asking the maintainer for a private reporting channel without describing the vulnerability. Private repositories use their existing private maintainer channel.

## Updates

Use the latest release where available and read each repository's release notes. Supported versions and backports are decided per project; this shared policy does not promise support for every historical version.

If a credential has been exposed, revoke or rotate it with its provider. Removing it from a commit alone does not invalidate it.
