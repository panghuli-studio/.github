# Contributing

Panghuli Studio is an independent development studio. Contributions are welcome; project-specific instructions take precedence over this shared guide.

## Before you start

Read the repository's README, license, and contributor instructions. Search existing Issues and PRs before opening a new one. For larger changes, describe the problem and proposed scope in an Issue first.

## Bug reports

Include the affected version, environment, minimal reproduction, expected behavior, and actual behavior. Remove credentials, personal data, and private infrastructure details from logs and screenshots. Use private security reporting for vulnerabilities.

## Pull requests

Keep each PR focused on one change. Explain the problem and resulting behavior, link the relevant Issue, and report the checks you ran. Add regression coverage for behavior changes, and update documentation when setup or usage changes. Do not include unrelated formatting or generated files.

Checks must pass before a change is merged. Maintainers may request changes or decline proposals that do not fit the project's scope. Release timing and support depend on the individual project.

Be respectful, assume good intent, and keep discussion focused on the work.
